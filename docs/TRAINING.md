# Selection, no-K/V mask learning, physical pruning and no-K/V recovery

The release exposes only the requested training stages. Every training launch checks `train.kv_weight == 0` and rejects a configuration that enables K/V matching. Disabling this loss does not remove the video features consumed by the action expert.

## Environment and workspace

Training uses Python 3.10, PyTorch 2.10.0, torchvision 0.25.0 and CUDA 12.8 wheels. The historical recipe uses eight 80 GB-class GPUs, global batch 256, substantial host RAM (up to 1 TiB in the original recovery launch) and shared storage. Allow at least 1.2 TiB free for full training states. Inference-only reviewers do not need this training allocation.

```bash
python -m pip install torch==2.10.0 torchvision==0.25.0 \
  --index-url https://download.pytorch.org/whl/cu128
python -m pip install -r requirements-train.txt
python -m pip check
```

`container/Dockerfile` records the environment for Apptainer execution. The container build is still unverified on the preparation host because the current account cannot access its Docker daemon. Build it on a machine with a container builder, then convert the resulting local image to a `.sif`. GPU launches use the assigned Slurm devices; they never select physical GPU IDs themselves.

```bash
docker build -f container/Dockerfile -t bagel-robotics-train:local .
apptainer build /path/to/bagel-train.sif docker-daemon://bagel-robotics-train:local
python run.py init --workspace /path/to/new-training-workspace
```

Edit that workspace's `assets.json` to provide absolute host paths. The wrapper mounts them read-only inside the container. Only the new workspace receives outputs; the original experiment directories are not modified.

## 1. Dataset selection

Use the unchanged selected panel as the reproducible default. Its fit, monitor and audit roles are validated for disjointness and complete action windows. The complete selection implementation is in `code/mask-no-kv/src/vpp2/full_mask/curation_v3*.py`, with configuration in the stage's `curation` section. The historical selection/review receipts are preserved alongside it.

## 2. Mask learning without K/V matching

The explicit stage configuration is `configs/stages/mask_no_kv.json`. It trains masks and video weights with ground-truth action loss, a reliability-weighted video term and size/discreteness regularizers. The action expert remains frozen. The size penalty replays the measured reference schedule; it is not advertised as newly calibrated in this experiment.

```bash
python run.py doctor --workspace /path/to/new-training-workspace --stage mask-no-kv
python scripts/train.py --workspace /path/to/new-training-workspace \
  --image /path/to/bagel-train.sif --stage mask-no-kv --action verify --dry-run
```

Run the same command without `--dry-run` inside a suitable Slurm allocation for the GPU check, then use `--action train`. A smoke check is required before the training launch. The preserved sources additionally enforce their CPU/GPU receipts and input identities. A new container/workspace smoke check is recorded separately from the historical evidence.

## 3. Physical pruning

For a completed, qualified no-K/V mask-learning run, use the same workspace and stage:

```bash
python scripts/train.py --workspace /path/to/new-training-workspace \
  --image /path/to/bagel-train.sif --stage mask-no-kv --action select --dry-run
python scripts/train.py --workspace /path/to/new-training-workspace \
  --image /path/to/bagel-train.sif --stage mask-no-kv --action prune --dry-run
python scripts/train.py --workspace /path/to/new-training-workspace \
  --image /path/to/bagel-train.sif --stage mask-no-kv --action verify-export --dry-run
```

Selection and pruning use eight workers; export comparison uses one allocated GPU. The selector requires a qualified checkpoint and checks that the mask indices and trained video weights belong together. The exporter slices the trained video tensors, emits the matching compact architecture and normalization, and verifies numerical agreement before recovery. It does not substitute the original dense teacher's weights.

`export-1500` is a separate historical export entry for checkpoint 1000's existing parent; it requires the recorded selected bundle and comparison receipts. It is not the output of the separate no-K/V mask-learning experiment.

## 4. Recovery without K/V matching, starting at 55

The evaluated checkpoint's retained recovery phases are:

| Entry point | Actual optimized updates | K/V-matching weight |
| --- | --- | --- |
| `recovery-55-to-250` | 56–250 | 0 |
| `recovery-250-to-1000` | 251–1000 | 0 |

```bash
python run.py doctor --workspace /path/to/new-training-workspace --stage recovery-55-to-250
python scripts/train.py --workspace /path/to/new-training-workspace \
  --image /path/to/bagel-train.sif --stage recovery-55-to-250 --action verify --dry-run
python scripts/train.py --workspace /path/to/new-training-workspace \
  --image /path/to/bagel-train.sif --stage recovery-55-to-250 --action train --dry-run
```

For the continuation, use `recovery-250-to-1000`, run its `verify` and `resume-check` actions, then `train`. These commands preserve optimizer state and the original schedule; loading only `video.pt` is not a faithful resume. The trainer exports paired compact video/action weights and matching metadata, checking tensor shapes and reload equality.

Recovery 0–55 is outside the requested workflow. The fixed historical recovery branch is bound to its own compact parent. A newly pruned model must establish its own verified recovery initialization; it must not reuse the old parent's identity or receipts. The supplied checkpoint remains the exact evaluated checkpoint 1000, as explained in [CHECKPOINT_IDENTITY.md](CHECKPOINT_IDENTITY.md).

## Validation scope

The package's CPU checks, real-data conversion check and unchanged checkpoint verification are recorded in `verification/release/`. Original eight-GPU training and numerical-export checks remain archived evidence.
